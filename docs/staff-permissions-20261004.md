# スタッフ入口・成績管理の権限（2026/10/04）

## 今回の設定

- スタッフ入口 `index.html`：講師マスターの権限1・2・3・4。
- 成績管理 `admin.html` と面談メモ `meeting_memo.html`：権限1・2・3・4。
- 資産管理台帳、請求書、QR登録・ポイント設定などの管理用認証：既存の権限2・3・4を維持。
- 成績Runtimeの生徒マスタ詳細・住所等の編集・同期設定：管理セッションと権限2以上が必要。

## 認証経路

入口3画面は `assets/js/staff-auth.js` を利用する。
`seiseki-admin-runtime-v1` の `staffLogin` が、従来と同じGASの講師マスター認証を呼び、サーバーが返した権限を採用する。
ブラウザーが送る権限値は採用しない。

権限1には `seiseki-grade:` で始まる暗号学的ランダムトークンを発行する。
DB `seiseki_admin_sessions` にはトークンのSHA-256だけを保存する。
権限1には既存の `systemPortalSessionToken` を渡さない。
成績用トークンは明示的に列挙された成績・通知表・志望校・学校マスタ・面談の操作だけを許可する。
生徒マスタの詳細編集や同期は、トークンのスコープと権限の両方で拒否する。

権限2以上は従来のGAS管理セッションを利用する。
他アプリの `verifySystemPortal` とQRの認証方式・許可権限は変更しない。

## 端末と失効

成績・面談の共用端末は従来どおり30分無操作でログアウトする。
成績用トークンの通常期限は8時間。自分の端末は既存の永続セッション方式を利用する。
ログアウトはDBのトークンを失効させ、成績用トークンについてGAS管理トークンの失効APIを呼ばない。
保存したトークンを復元するときもサーバーに確認する。

重要な運用上の限界：ローカル発行した成績用セッションは講師マスターを毎回読み直さない。
権限を取り消す場合、講師マスターの変更に加えて、対象講師の `seiseki_admin_sessions` のセッションを失効させること。
これは既存の成績Runtimeの永続キャッシュにも必要な運用である。
次の改善では権限変更と成績用セッション失効の連動を実装する。
認証情報やトークンの実値を台帳・GitHub・ログへ記録しない。

権限0拒否、権限1の成績閲覧・書込の認可、管理機能拒否、偽造・期限切れ拒否、
ログアウト失効、権限2の既存経路、端末別保存と30分無操作ログアウトを確認する。
書込テストでは認可後のmutation ID必須判定までを確認し、実データは変更しない。
7049の実ログインは、認証情報送信に対する自動承認審査の拒否により未確認。

## 今後の推奨（今回未実装）

アプリごとに「利用・閲覧・入力・削除・設定変更」を分けて権限表を一元管理する。
講師は成績閲覧・入力、運営担当は請求等、塾長は権限変更・一括削除などを担当する。
サーバーは毎要求で権限を確認し、直URLや画面の保存情報だけでは許可しない。
