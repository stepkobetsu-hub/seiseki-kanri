# STEP 時間割

本番: https://stepkobetsu-hub.github.io/seiseki-kanri/timetable.html

スタッフ用アプリの「時間割」から開く。講師番号・パスワードで権限1～4が利用でき、共通セッションをログアウトまで保持する。最初は教室と1～6週間を選び「未作成の日を追加する」を押す。最後に開いた教室は同じブラウザーに保存する。

## 作成と変更

- 生徒マスタの時間割を既存の `student_directory_details` 同期経由で読み、新しい日だけ作成する。通常画面はPostgresだけを読む。
- 作成済みの日は生徒マスタ変更・再生成・基本配置変更でも上書きしない。生成と特訓の先行登録は同じ日付のトランザクションロックで調整する。
- 添付の神領・大手の時間割マスタから講師配置93件をDBに取り込んだ。現マスタの校舎・曜日・氏名・科目と一致するものだけ使用し、担当不明は「担当未定」にする。生徒名付きの元データは公開リポジトリに置かない。
- 「曜日別の基本配置」で今後追加作成する日の講師・班を設定する。すでに作成した日の担当変更は授業を押して行う。
- 日付・時間変更で振替。振替先の日も作成済みである必要がある。元日と先日を一括保存し、版が古いと全体を拒否する。
- 通常授業は同一講師・同一班の2人まで。プロは同一クラス10人まで。特訓・土曜特訓は複数名、監督は担当枠として扱う。別クラス・通常授業との時間重複を検出し、欠席・休講は担当人数から除外する。
- 作成時点のマスタ同期が30分以上前なら生成を止める。権限2以上の「マスタを更新」で既存の同期APIを呼べる。これは表示・印刷の通常経路には入らない。

## 日々の案内

表示日を選んで「日々の案内を印刷」。日付・曜日・日本時間の出力時刻と改訂番号を表示し、講師ポータルQR、生徒・講師別メッセージを付ける。添付と同じA4横向きが標準。授業なしの時間帯は印刷では省略する。メッセージは共有保存され、印刷前に最新データを取り直す。長いメッセージや授業・メモが多い日は複数ページになる場合がある。

## 特訓連携

`step-message-center` の実送信履歴から「特訓部屋」の案内日・時間と、送信成功した対象者を取得する。メールやLINEはこの連携から送信しない。

- 配信画面で送信成功後に確認を開始する。ブラウザーを閉じてもpg_cronが3分ごとに確認する。
- 予約登録時点では入れず、実際の配信後の履歴から入れる。
- 特訓の対象日が未作成ならイベントを待機させ、日付生成時に反映する。
- 送信履歴ID＋生徒IDで重複防止。自動登録後の移動・削除は同じ履歴の再確認で戻さない。
- 氏名は空白・全半角・髙/高・﨑/崎を正規化して照合。同姓同名で一意に決められない場合や日時を読めない場合は自動登録しない。
- 時間割を開いた時の確認と「特訓配信を確認」も使用できる。標準の監視は最新100件の送信履歴。

## データと検証

`step_timetable_days`, `step_timetable_rules`, `step_timetable_events`, `step_timetable_service` はRLSを有効にし、一般クライアント権限を取り消す。データはカスタム認証するEdge Functionだけから読む・保存する。共通セッションをサーバーで検証し、権限0と未認証は拒否する。

構文検査、ドメインテスト5件、現マスタによる両校1週間の生成検証、生成上書き防止、版競合拒否、特訓の先行登録・重複防止、未認証401、本番での送信履歴連携を確認。ブラウザーでの実画面と実プリンターの印刷は未確認。
